# decisions 0.2.0, part 2: Gemini and Venn in three vignettes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gemini in "Choosing a model" and "Images" (with and without references), and Venn with a calibration step in "Open models", from saved runs that a reader can make again.

**Architecture:** New cases in `data-raw/vignette_results.R` run only the new provider and merge into the saved results, so the other providers are not called again; the vignette chunks show the full code with every decider. Venn gets its own saved file, so the Laya results stay.

**Tech Stack:** R, decisions (branch with `decider_gemini()` and `decider_venn()`), yardstick, probably (mgcv), the local Venn server.

**Spec:** `replication_materials/plans/2026-11-24-decisions-0.2.0-design.md` section 3 (D313); D301, D302, D306.

Paths: `decisions/` is the package; `study/` is `fine_tuned_jev`. The map of the current pipeline is in the report of 2026-11-24 (vignette_results.R lines 26, 226-330, 332-410, 412-484, 590-604).

## Global Constraints

- Branch `vignettes-gemini-venn` of decisions, from `deciders-gemini-venn`. It merges after part 1.
- Paid calls: Gemini only, budget row of D301; every call logged in `study/replication_materials/calls/gemini-calls.csv` with `log_decide("gemini", ...)`, purpose prefix `decisions-0.2.0-`. Venn calls are local and free.
- The scripts read the keys from `study/.Renviron` and `study/.env` (the Gemini key is only in `.env`); no key is printed or written.
- "No result in a vignette that a reader cannot rerun from `data-raw/`." "No claim in a vignette that the numbers do not support."
- The `script = TRUE` chunks of a vignette show the code that a reader runs (all deciders); a `*_gemini` or `*_venn` case of the script runs the same lines for the new decider only and says so in a comment.
- Venn runs with `max_active = 1`; Laya and Venn are never up together (both use port 8000).

## Review Focus

1. A merge that drops or reorders the saved answers of the other models: each merge case checks that the old elements are byte-identical after the merge.
2. A Gemini run whose rows are not in input order, or with row errors: `report_errors()` and a check of the row count before the save.
3. Venn up on port 8000 while a Laya case waits: the Venn case waits for `reader == "ready"`; `wait_for_laya()` refuses a health answer with a `reader` field.
4. A calibration fitted and scored on the same rows: the split is fixed (seed, stratified by class) and the vignette shows the halves.
5. Prose that names "three models" or fixed numbers that change: every fixed number in the changed sections comes from the saved data in an inline chunk, or is checked with `stopifnot()`.
